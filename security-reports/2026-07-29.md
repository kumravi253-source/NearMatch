## Findings & Actions Taken

### npm dependency vulnerabilities (WARN)
`npm audit` reported 27 vulnerabilities: 19 high, 8 moderate, all with `fixAvailable`. Every one of the 19 high-severity findings traces back to the same root cause: the installed `expo@57.0.8`-era toolchain and `react-native@0.86.2` pull in vulnerable transitive deps (`@react-native/*`, `babel-*`, `postcss`, `glob`, `minimatch`, `rimraf`, `chromium-edge-launcher`, `test-exclude`, etc.). `npm audit`'s own `fixAvailable` metadata marks every one of them `isSemVerMajor: true` — meaning the only fix path is `npm audit fix --force`, which would bump Expo/React Native to a new major version. Per the auto-fix rules, this is a "do not auto-change, flag for founder" case, not a "just fix it" case — an unattended major-version bump to the framework that runs the entire app is exactly the kind of breaking change that shouldn't happen without you watching. I ran plain `npm audit fix` (no `--force`) as instructed; it found and applied one safe, non-breaking patch (`brace-expansion` 2.1.2→2.1.3, a nested dep of `expo`) and committed it. Vuln count is otherwise unchanged because nothing else qualifies as non-breaking.

### Unconfirmed user account (WARN, minor)
One user, `qadpdptest20260724@nearmatch.in`, created 2026-07-23 and still unconfirmed after >48h. Name pattern strongly suggests an internal QA/DPDP-consent test account rather than abandoned real-user signup or spam, but flagging per the check's criteria since I can't confirm intent from the auth record alone.

### Everything else
No unauthenticated data leaks, no secrets in source, RLS intact on every table with policies matching (or exceeding) the expected model — e.g. the `messages` INSERT policy blocks messages between users who've blocked each other at the database level, not just the app layer, and `record_swipe` is a `SECURITY DEFINER` RPC with rate limiting baked in (which is why `swipes` only shows a SELECT RLS policy — inserts are intentionally routed through the function, not direct REST).

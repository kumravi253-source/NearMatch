## Findings & Actions Taken

1. **🚨 CRITICAL (carried forward, unresolved) — `razorpay_order_attempts` anon-SELECT policy.** `pg_policies` still shows `anon_select_razorpay_order_attempts` with `roles={anon}`, `cmd=SELECT`, `qual=true` — an unrestricted read policy for the anonymous role. Live-tested: anon key currently gets `42501 permission denied` because no `GRANT SELECT` has been issued to `anon` at the table-privilege level, so the policy is dormant, not exploitable today. But the policy itself is still wrong-shaped and would silently expose all rows (order attempts, IPs, timestamps) the moment any future migration adds `GRANT SELECT ON razorpay_order_attempts TO anon`. Per the audit's auto-fix rules, RLS policy changes are never auto-applied — this needs explicit founder review and either a scoped policy or removal of the anon SELECT policy entirely (anon almost certainly only needs INSERT here, for pre-auth order-attempt logging).

2. **⚠️ WARN — npm audit: 11 high-severity vulnerabilities, transitive-only.** Note: the top-level stack is already current (`expo ~57.0.11`, `react-native 0.86.2` — confirmed installed, not just declared; last bumped in commit `d1f419d "Bump Expo SDK 57 packages to latest patch versions"`). This corrects the prior report's note that an Expo 53→57 upgrade was still pending — that upgrade is done. The 11 vulnerabilities are all in *nested* transitive packages (`metro`, `metro-config`, `metro-transform-worker`, `@expo/metro`, `@react-native/community-cli-plugin`, `@react-native/virtualized-lists`, `image-size`) that some sub-dependency still pins to older ranges. `npm audit fix` (non-forced) was run as an auto-fix attempt: it did not reduce the vulnerability count (still 11 high after) but did rewrite `package-lock.json` to insert an additional, inconsistent `@expo/metro-config@57.0.7` entry alongside the existing tree — a lockfile change with no security benefit and a real risk of build/dependency-resolution breakage on a live app. **This change was reverted** (`git checkout -- package-lock.json`); nothing was committed. `npm audit fix --force` would apply semver-major overrides and was not attempted — that needs a deliberate, tested upgrade session, not an unattended auto-fix.

Unchanged since 2026-08-02 per prior reports.

4. **Stale unconfirmed test account** — `qadpdptest20260724@nearmatch.in`, created 2026-07-23, still unconfirmed. Cosmetic; safe to delete or ignore, matches prior reports.
